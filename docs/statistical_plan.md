# 固定標本による対比較の検証設計

主評価項目は「180秒以内に配送成功し、衝突・ニアミスが0の走行の割合」とする。AI対距離方式、AI対ルール方式の2比較を事前に指定し、片方だけの結果から全方式への優位性を主張しない。

各比較は同じ環境の二値結果を対応させ、AIだけ成功・相手だけ成功の組数から正確McNemar検定（両側）を行う。2比較にHolm補正を適用し、補正後p<0.05かつ対応する95%区間の下限>0の場合だけ当該比較の優位性が統計的に支持されたとする。区間はシナリオ内で対応を維持して再標本化する5,000回のブートストラップ、乱数426で算出する。p値や信頼区間は絶対的な安全保証ではない。

最終標本数は600組、3方式で1,800走行。crossingは20000–20199、clutterは30000–30199、closureは40000–40199で、シナリオ間でもシードを共有しない。動的環境は400組を含む。途中経過から標本数・評価指標・モデルを変更せず、有意になるまで試行を追加しない。中断時は同一入力の残りを再開し、成功・失敗とも除外しない。

標本数の計画では5ポイントの効果、対応する結果の不一致率0.15を仮定した。2比較を保守的なBonferroni閾値で近似すると、600組で検出力約0.83となる。未知の真の効果や不一致率に対する保証ではない。効果が小さければ検出力も下がる。従来の90組は探索的な参考評価とし、新しい600組をパラメータ調整に使用しない。

配送検証は各シナリオseed 1000–1009の30組に拡張する。AIの重み・低リスク域閾値だけでなく、ルール方式の重みも独立に選ぶ。既存3環境・seed 310/311の6組で安全配送を維持する候補を優先し、開発集合の安全配送数、配送成功数、衝突数、失敗時180秒の配送時間の順に選ぶ。選択に実行負荷で変わるCPU時間は使用しない。

距離・センサー・速度と加速度制限・進捗監視・予測領域・安全停止は全方式で共通とする。安全の閾値は緩和しない。4プロセスで実行し、方法の実行順をシードから無作為化する。並列時の壁時計時間と、各プロセス自身のCPU時間を区別して記録する。

配送時間・距離・停止時間などは副次的な記述評価とし、主評価項目で有意でない結果を別の指標へ置き換えて結論を変えない。失敗は全件表示し、終了までの実測時間と失敗を180秒とする指標の両方を保存する。デモは結果に依存せずclosureの最小最終シード40000を使う。
